## 3. The design, contract by contract

**E1 — kinds registered once.** The kinds are a table in the kind profile
(`lib/py/bbx/config.py`), `[expectations].kinds = [[extension, family,
disposition]]`; the frame-driven profile carries bbh's five (`masked`
temporal EVAL, `skip` — SKIP, `sha1` exact N/A, `diverge` temporal EVAL,
`pending` — NOT-EVALUATED) so `bbx expectations enumerate` prints bbh's
`name|kind|disposition` lines byte for byte; a kind with no row is
UNKNOWN-KIND and non-zero (R23). The kind-blind default carries `skip`,
`sha1`, `pending` only: a kind with no comparator family has nothing else to
register.

**E2 — unratified is red.** `.pending` and NO-EXPECTATION stay the suite's
FAILUREs with bbh's text.

**E3 — the register.** `PROVENANCE.tsv` beside the expectation tree, class
EQUAL to one of R11's eight, complete both ways; `testimony` never green;
`fixture` counted as not evidence about a real subject (R24). The screen's
"expectations relied upon" line becomes the histogram of classes over the
set the run used, read from the kept run.

**E4 / §3.4 — anchored outside the subject.** The `.sha1` kind is `self`
class by construction (bbh: "answers 'did this build change since I froze
it'"); the register cannot rank it higher, and the screen says how many of
the run's expectations are `self`.

**C1 — the temporal family**, lifted verbatim: flicker, window, composite,
the frozen first-divergence constant, thresholds declared once. The
exact class is the family-blind default (`cmp`). Set/multiset, schema and
tolerant-numeric are S3–S4's, and R23 fixes where they will plug in.

**C2 — the spec line and the one dispatcher.** `<class> <baseset> <args>`
unchanged; family and view come from the kind (R23). `lib/sh/compare.sh`
holds `compare_check <expdir> <name> <kind> <spec> <runmask> <log>`; the
temporal branch is bbh's `masked_check` line for line, including the
baseset/mask guard.

**C3 — FAIL-SHORT is its own finding.** bbh prints it inside the flicker
verdict (`FAIL masked-flicker: got 'FAIL-SHORT …'`) and the suite line reads
FAIL. The text is frozen (C4), so the distinction is carried by the KEPT RUN:
`bbx-run-suite --log DIR` writes `results.tsv` with one row per scenario —
`scenario, kind, class, verdict, finding` where `finding` is one of
`diverged | short | nondeterministic | run-fail | unregistered | pending |
no-expectation | mask-mismatch | unknown-class | skip | pass` — and the
readout counts `short` separately from `diverged` (BBX-4). Nothing printed
changes.

**C4 — verdict text frozen.** The 62 lines counted in §2. The fidelity gate's
must-fire perturbs one in a shadow copy.

**C5 — proposer = enforcer.** `propose_temporal.py` imports the same
`thresholds.py`; `gates/thresholds.sh` proves a consumer override reaches
every importer and that a proposed line dropped into a spec passes.

**C6 — not expressible means root-cause.** The proposer's "does not
re-converge: not expressible" line is frozen text too.

**R25 — loosening refused without a ruling row.** `thresholds.py` compares
the consumer value to the kind profile's in the key's looseness direction and
refuses (exit 3, one line) unless `[thresholds].rulings` names the key.

**The suite runner.** `bin/bbx-run-suite`, bbh's loop with three additions
that print nothing: `--log DIR` (the kept run above, D22's shape), the R25
refusal at start-up, and the R26 driver-home resolution. `runs_per_replay`
stays 2 and becomes a defaults-register row of class `principled` (BBX-14).
`hash_cmd` stays bbh's `shasum` in the frame-driven profile (fidelity) and
gets a portable kind-blind default (a python one-liner) whose detector is
R21's Linux run.

**BBX as its own consumer (R14).** BBX's `self` kind gets no suite in S2:
BBX has no scenarios to replay. The `self` battery gains the S2 gates listed
in §2 and the fidelity gate below.

## 5. Controls the slice must demonstrate (from `docs/slices.md`, made concrete)

| control | shape | where | fires when |
|---|---|---|---|
| window on a bit-identical pair | known-bad | `temporal.sh` | `compare_window` FAILs a pair with no divergence |
| FAIL-SHORT vs FAIL | known-bad | `temporal.sh`, `suite.sh` | a log cut inside a divergence reads FAIL-SHORT in the comparator and `short` in the kept run's `finding` column, never `diverged` |
| a nondeterministic pair | known-bad | `suite.sh` | `FAKE_NONDET=1` yields the NONDETERMINISTIC line before any class is consulted |
| a loosened class with no ruling row | known-bad | `thresholds.sh` | `flicker_max = 3` with no `[thresholds].rulings` entry: every importer refuses with the same line; `= 1` (tighter) passes |
| perturbed `.sha1` / `.masked` / `.diverge` | perturbed-copy | `suite.sh` | each turns the suite RED with bbh's text |
| the hermetic scrub | known-bad | `suite.sh` | a `POKES` in the environment does not reach the driver through the suite while it demonstrably reaches it directly |
| a file with no row; a row with no file; a class outside R11 | known-bad | `provenance.sh` | each is a FAIL naming the file |
| an unknown expectation kind | known-bad | `expectation_kinds.sh` | `.weird` is UNKNOWN-KIND and non-zero |
| proposer = enforcer | known-bad | `thresholds.sh` | a proposed line dropped into a spec passes; with a shadow `thresholds.py` changed for the proposer only, the pair disagree and the gate says so |
| verdict-text | perturbed-copy | `fidelity_bbh_s2.sh` | one changed string makes a diff non-empty |

## 6. What the readout gains (RO1)

- `expectations relied upon:` the histogram by R11 class over the set the
  kept suite run used, `self` and `fixture` called out; still "none
  registered" for a run with no suite.
- `comparator classes:` the classes the profile declares, and for each
  whether it has ever PASSed on a pairing whose expectation is not
  `fixture`-class — in S2 every class reads "never on a real pairing", which
  is the true sentence.
- `findings:` `short` counted apart from `diverged` (BBX-4).
