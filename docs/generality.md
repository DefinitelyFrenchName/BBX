# The generality proof — two non-frame subject kinds (ruling R2)

**Shape: proposal (session 1, 2026-09-09). R2 ruled 2026-09-09 with two additions (R14, R15), folded in below. Nothing built.**
CLAUDE.md §5 sets the minimum: at least two subject kinds that are not
frame-driven, exercised end to end, one involving no executable. One
non-frame instance proves nothing; two prove the abstraction; the third —
bbh's own fake machine, the frame-driven kind — shows it was not a coincidence
and is also the fidelity lineage (`docs/fidelity.md`).

What "exercised end to end" means here, for each kind: a FIXTURE SUBJECT
inside this repository with known truth; a driver under the D-contract; an
observation in the O-grammar; expectations with provenance; at least two
comparator families; a gate battery with declared must-fire controls that are
shown to fail; a readout stating what the green does not assert. Every
scenario runs twice (BBX-14). All fixture content is chiral (BBX-15): no
palindromes, no symmetric ranges, no values equal to their mirror, so a
mirror, order or orientation error cannot hide.

## Kind A — a DOCUMENT SET (no executable)

Ancestors: SMS `tools/checkdocs.py` (quote the claim from the doc → derive the
same fact from the artifact → compare; coverage printed, never fatal;
`tools/checkdocs.py:15-22,40-43`), VS L3 `tools/checkdocs_rom.py` (the
PARAPHRASE class; the view is the access mode; coverage frozen as a multiset —
`docs/census/vampiresaved.md`), BBX-18, BBX-19, BBX-20.

| contract | instance |
|---|---|
| SUBJECT | a directory of markdown documents plus the ARTIFACT they describe (a TSV or JSON table). Views: *document text* (claims quoted) and *artifact* (values derived). Identity: a hash over the document set and the artifact. |
| SCENARIO | a CLAIM SET: which documents, which artifact, which view, which sentence forms are bindable. |
| OBSERVATION POINT | a claim id (document, line, form). Tokens: the quoted value, the derived value, the binding status (`BOUND`, `PARAPHRASE`, `UNBINDABLE`). `END <n>` with n = claims seen. |
| DRIVER | `<docset> <claim-set> <out>`; extracts claims of the declared sentence forms (the SMS convention that prose form is a contract with the checker, `docs/game/README.md:82-113`), derives from the artifact, writes the log. Refuses a sentence form it does not implement (`REFUSED`, exit 3); exits 1 if the artifact cannot be read. |
| EXPECTATION KINDS | the claim inventory (a multiset of claim ids, compared both ways, BBX-17); per-claim expected agreement; the COVERAGE number, frozen and allowed to move in one direction only (VS rule-5 BAKED inventory "can only shrink"; VS L3 covered set frozen as a multiset). |
| COMPARATORS | *exact* (quoted == derived); *set/multiset* (inventory); *schema* (the artifact's shape before any value is trusted). |
| PROVENANCE | the artifact is class `fixture` (synthesized by us with known truth, R11) — which is exactly why the fixture is not the proof of correctness of any real document set, and the readout says so. |
| CONTROLS (must fail) | an edited document whose quote no longer matches → FAIL loudly (SMS step 1); the artifact shifted by one row (the base+1 analogue of SMS `checkdocs.py:465`) → every claim FAILS; the same document handed twice → identical (BBX-14); a deliberately wrong claim planted in the fixture → FAIL on that claim only; a paraphrased claim → `PARAPHRASE`, never green; an unbindable claim → counted in coverage, never silently dropped (SMS `UNENCODABLE`). |
| DOES NOT ASSERT | prose, reasoning, causal claims, anything the artifact cannot decide (SMS `checkdocs.py:45-49`); the truth of the artifact itself. |

**The fixture subject.** `fixture/docset/`: a synthetic artifact of 12 named
records with asymmetric values; three documents quoting 20 claims in the
bindable forms; one deliberately wrong claim; one paraphrased claim; one
unbindable claim (an absence — "nothing writes X" — which BBX-7 says needs a
positive control, so it is listed, not bound); one claim quoting a number that
appears in no log (the skills-lock analogue). Generated by a script with a
`--check` mode so the fixture cannot drift by hand (SMS `tools/mk*.py`
convention, 6 generators). Numbers above are the *design*; the built fixture's
counts are measured when it exists.

## Kind B — a COMMAND-LINE TOOL (executable, not frame-driven)

Ancestors: bbh's fake machine (`example/fakesys/fakesys.py`, every class
ROM-free) — the shape of a fixture subject whose *features* produce every
comparator class; SMS `tools/cliguard.py` (a tool must refuse options it does
not define, 12-case selftest); SMS `verify_dspdiff.sh:10-16` (DETERMINISM /
INERTNESS / SENSITIVITY / NEGATIVE as a four-stage self-check).

| contract | instance |
|---|---|
| SUBJECT | an executable plus its declared interface. Views: stdout, stderr, exit status, emitted files. Identity: a hash over the executable and its declared version output — the version output is the subject's own metadata and is therefore NOT the identity (CLAUDE.md §3.4); the hash is. |
| SCENARIO | an invocation: arguments, stdin, environment, working directory, expected emitted files. |
| OBSERVATION POINT | an output line number or a named field of a structured output; tokens: the value or its hash; the exit status is its own line; `END <n>`. |
| DRIVER | `<toolset> <scenario> <out> [sandbox]`; the sandbox is the working directory; the environment is scrubbed of the family; a variable the driver cannot honour (a stdin it cannot feed, a file capture it cannot do) is `REFUSED`. |
| EXPECTATION KINDS | frozen hash of stdout; a spec line per class; a schema for structured output; a multiset for unordered output; a tolerant-numeric class per named field, ratified. |
| COMPARATORS | *exact*; *set/multiset* (unordered listings); *schema* (JSON shape); *tolerant-numeric* (a field that legitimately varies within a *measured* band, the band frozen as an expectation, never a tolerance). The temporal family is not needed — which is the measurement that it is one family among several. |
| PROVENANCE | `fixture` for the fake tool; for a real tool the reference is the class `reference` (an upstream artifact, a specification) or `self` (our own build: currency, never correctness). |
| CONTROLS (must fail) | one byte of a shadow copy of the tool perturbed (`[BBH-59]`) → FAIL; a `--nondet` feature → NONDETERMINISTIC before any class; a `--crash-at n` feature (death by a signal) → the guard: exit 2, `END-CRASH`, the partial output kept as the bug report, never compared (D4, bins B-X19; a tool's ordinary non-zero exit is an OBSERVATION, not a failure — corrected 2026-09-10 at R35, retraction X13); an unknown option → the tool refuses (SMS cliguard); a loosened tolerant-numeric class with no ruling row → refused by the checker. |
| DOES NOT ASSERT | performance; behaviour on inputs outside the scenarios; anything read only through stdout when the tool also writes files the scenario did not capture. |

**The fixture subject.** `fixture/fakecli/subject/fakecli.py` (generated by `mkfakecli.py`; in its own directory so the whole-set key covers the subject alone — corrected at bbx-13, X14): deterministic;
features selected by flags — `--emit-json` (schema), `--unordered` (multiset),
`--band <field>` (a tolerant-numeric field varying within a band seeded from
the arguments), `--nondet` (mixes the clock in), `--crash-at n`, and an
unknown-option refusal. Outputs are chiral by construction.

## Kind C — the FRAME-DRIVEN kind (the lineage)

bbh's fake machine and example consumer, unmodified, driven through BBX's
contracts. Its proof is fidelity, not generality: `docs/fidelity.md`.

## Kind D — BBX ITSELF (self-validation, ruled R14)

Not a fourth kind: BBX's own tree driven through kinds A and B. Its documents
(`docs/census/*.md`, `docs/bins.md`, every readout) are a document set whose
claims are the counts, re-derived by the commands beside them — the recount
gate (R9) is the first instance and the first gate BBX runs; its gates,
runners and registries are command-line subjects whose observations are the
verdict ROWS of a kept run, read by column name. NOT the anti-orphan report:
measured at bbx-18 (G34), the runner NAMES a gate that is in no registry and
exits 0 all the same, so no token of the self subject carries it and BBX-9's
orphan direction is unenforced until R45 is answered (corrected here, BBX-19,
retraction X35). The maintainer's condition is
"without degrading its rules": a self-validation gate is subject to G3 (its
controls must fire), and the custodian outside the loop is bbh — the fidelity
rows are what a shared convention error cannot fool (BBX-15). On every
platform of R3 (macOS, Linux, Windows/WSL), which is also how fragmentation
is measured rather than feared.

## Adapters — external test frameworks as drivers (ruled R15)

An adapter is a driver of kind B that runs a framework's own suite as the
scenario and maps each test case to an observation point (abstraction D7).
Two frameworks are needed before the adapter is called generic (BBX-25); the
candidates are chosen when slice S4 opens, from what the first real consumer
already uses. What the adapter does NOT assert: that the framework's tests
are good — it asserts that they ran, deterministically, and produced the
frozen observation.

**Built at bbx-18 (S4 step 5), and here is what it measures.** R37's two
frameworks are Python's `unittest` (`drivers/unittest.sh`) and BBX's own static
runner through its own dispatcher (`drivers/gates.sh`), both drivers of kind B
over one core — `lib/py/bbx/cli.py`'s sandbox, hermetic environment, recording,
timeout and log grammar, which now has three consumers, so BBX-25 is met for the
core with one to spare. Each maps its framework's report to observation points
by NAME: a per-case line's first field and its verdict word for the one, a kept
`results.tsv` row's `gate` and `verdict` columns for the other. Neither maps
what the framework TIMED (`Ran 2 tests in 0.003s`, the `seconds` column), because
a clock in an observation is a nondeterminism the harness would blame on the
subject. Two consumers were built with them: `fixture/unittest/` (8 cases in 2
modules, covering all six words of the closed verdict vocabulary, one of them a
case that FAILS BY DESIGN so the observation carries a red token the frozen
truth expects) and `fixture/selfgates/` (a synthetic `self`-kind consumer of 7
stub files whose 6 registered rows read PASS SKIP PASS MISSING FAIL PASS in a
deliberately unsorted registry order). Both fixtures' expectations are class
`derived`, not `fixture`: the verdict words follow from each framework's own
stated contract, and the generators write the truth logs from the design through
the token vocabulary rather than by running the adapter. `gates/adapters.sh`
declares 6 controls and fired 9 times over 14 suite runs in 97 s.

## What the proof measures

When kinds A and B exist, the readout of that slice reports, as numbers with
the command that produced them:

- harness files shared by all three kinds vs files specific to one kind;
- comparator families exercised per kind (A: 3, B: 4, C: 2 — the *design*
  target; measured when built);
- controls declared / fired per kind, and that each failed on purpose;
- every expectation's provenance class;
- for each kind, the sentence "what this green does not assert";
- the self-validation gates (kind D) and their control counts, per platform.

A generic thing needs two instances (BBX-25): any component used by only one
kind at the end of the proof is moved to that kind's profile and reported.

## What this proof does NOT establish

That BBX works on a *real* document set or a *real* tool (both fixtures are
`fixture`-class); that a fourth kind (an FPGA flow, a data pipeline, a model
evaluation — R2's declined alternatives) fits without a new comparator family;
anything about subjects that cannot be driven deterministically (R5).
